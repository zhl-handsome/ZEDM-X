# ZDEM-X MPI 版性能记录(第一阶段:CPU 通信层)

日期:2026-08-18
分支:`feat/mpi-cpu-comm`
硬件:单机 MS-MPI 多进程(与 GPU notes 同机:RTX 4090 D 主机,32 逻辑核;进程间走共享内存通道,无网络)
构建:Release,纯 double(MPI 版为 CPU 谱系,无精度变体)
相关:验证阶梯与设计见 `2026-08-18-mpi-dem-design.md`;CPU/GPU 单进程对照基准取自 `2026-08-18-gpu-performance.md`
算例:`scratch/pile64.txt`(64 香蕉两层堆积,间距 0.18,seed 42,dt=2e-5)

## 结论

- **受控 20k 窗(自由落体+首轮触底):4 进程 ms/步 = 2.091,vs 单进程 MPI(5.676)加速 2.71×,vs zdem_cpu 参照 11.41 加速 5.46×**(启动已扣除)
- **步时强依赖接触密度**(V3 全程实测):n=4 自由落体 0.575 → 首轮触底 3.84 → 密集成堆 6.36 → **稳态(100k–248k,contacts 98–101)7.00 ms/步**(含输出摊销 ~0.06);引用任何 ms/步必须带窗口
- 稳态接触段 vs zdem_cpu 密集窗参照 11.41(tri 遥测含在内)只有 **~1.6×**——"5.46×"是自由落体窗 MPI 对密集窗 CPU 的跨窗对照,只能当量级参考;同窗(前 20k)对照为 3.54×
- n=2 加速 2.12×(超线性,>2):每 rank 工作集减半的缓存效应 + O(n²) 枚举规模按 rank 二分,抵消了每步 ghost 重建开销
- n=4 效率降至 68%(20k 窗):步时中约 **32% 为不可扩展开销**(每步全量 ghost 重建/迁移重打包 + 静态分解负载不均);64 粒子量级下这已是单机共享内存形态的实际天花板区间
- **负载不均是 n=4 的主要限制**:4x1x1 分解下 pile64 初始 rank_n=8,24,24,8(两端薄中间厚),稳态 6,26,25,7——最重 rank 持 41% 粒子,步时由最重 rank 决定
- **与 zdem_cpu 的对照含口径差**(见下节披露):11.41 参照含 CPU 驱动每步环路遥测(tri-tri 管线,18k 步时 ~2.1M tri_checks/步、tri_ms≈11);MPI 版不含该管线,n=1 即比 zdem_cpu 快 2.01×,其中相当部分来自遥测差而非并行
- mpiexec 进程启动开销(steps=1 实测含 config+网格加载+1 步+1 帧):n=1 0.379 s / n=2 0.437 s / n=4 0.586 s——长跑可忽略,已从计时中扣除

## 测量方法(沿用 GPU notes 约定)

1. 受控无输出窗口:`steps=20000, output_interval=25000`(仅 step 0 写一帧),`time mpiexec -n <n> ...` 取 real 墙钟
2. 启动扣除:同 config 改 `steps=1` 实测整进程墙钟(n=1/2/4 各测一次,见上);ms/步 = (real − 启动)/20000
3. 机器静默(无其他负载),三次测量串行执行;计时 run 的 step 0 `rank_n` 行与 24k parity run 一致(确定性轨迹)
4. 参照值:zdem_cpu pile64 **11.41 ms/步**(GPU notes 同方法 50k 受控窗口);同窗(前 20k、自由落体为主、墙钟含输出摊销)CPU 为 7.398 ms/步

| n | dims(自动) | real | 启动 | ms/步 | vs n=1 | vs zdem_cpu 11.41 |
|----|----|----|----|----|----|----|
| 1 | 1x1x1 | 113.895 s | 0.379 s | **5.676** | 1.00× | 2.01× |
| 2 | 2x1x1 | 53.995 s | 0.437 s | **2.678** | 2.12× | 4.26× |
| 4 | 4x1x1 | 42.410 s | 0.586 s | **2.091** | **2.71×** | **5.46×** |

- 自动分解恒取长轴:全局盒 [-1.147 1.147]×[-0.787 0.787]×[-0.267 0.967],x 最长 → 1/2/4 进程分别为 1x1x1 / 2x1x1 / 4x1x1(切面 x=-0.5735, 0, +0.5735),ghost=0.207
- 效率:n=2 106%(超线性),n=4 67.9%;n=4 步时中不可扩展份额 ≈ (2.091 − 5.676/4)/2.091 = **32.1%**(ghost 重建 + 迁移重打包 + 负载不均合并估计,未单独仪器化)
- **vs zdem_cpu 列为跨窗对照**(MPI 侧自由落体窗 vs CPU 侧 50k 密集窗),只能当量级参考;同窗(前 20k、CPU 墙钟含输出摊销 7.398)则 n=4 为 3.54×;稳态接触段见下节(~1.6×)。vs n=1 列同窗同口径,是并行收益的可靠度量
- n=1 稳态(接触密集段)ms/步未测(计时协议固定 20k 窗),如需稳态加速比需补 250k 单进程 run

## rank_n 分布(负载演化,V3 全程 250k 日志)

| step | contacts | rank_n | 事件 |
|----|----|----|----|
| 0 | 0 | 8,24,24,8 | 初始:两端 slab 各 1 列 8 粒,中间各 3 列 24 粒 |
| 20000 | 50 | 7,25,25,7 | 首次迁移(边缘粒子向内滚过 x=±0.5735)——**与接触同时发生** |
| 28000 | 81 | 6,26,25,7 | 继续内迁,此后 250k 全程稳定 |
| 88000–248000 | 98–101 | 6,26,25,7 | 稳态:最重 rank 26/64 = 41% 粒子 |

迁移方向实测为**边缘向内**(堆积收拢),非向外铺开;rank0→rank1 两粒、rank3→rank2 一粒,均发生在成堆接触活跃段。

## V3 算例剖面(pile64 × 4 进程,250k 步全程)

- 端到端墙钟(首/末帧 mtime 法,GPU notes 同款):**1624.7 s ≈ 27.1 min**,均摊 6.551 ms/步(含输出);前 ~10 min 与 24k parity 复验 run 并行执行,稳态段(100k+)无并行干扰
- 分相步时(帧 mtime 差,含输出摊销 ~0.06 ms/步):

| 相 | steps | contacts | ms/步 |
|----|----|----|----|
| 自由落体 | 0–10k | 0 | 0.575 |
| 首轮触底 | 10k–20k | 5–50 | 3.84 |
| 密集坍缩 | 20k–30k | 64–81 | 6.36 |
| 成堆过渡 | 30k–60k | 79–100 | 6.75 |
| 稳态 | 100k–248k | 98–101 | **7.00** |

- contacts:0(0–8k)→ 5(10k)→ 81(28k)→ 98–101(88k 起稳态);与 GPU 版同算例剖面一致(96@40k / 104@248k)
- 稳态 7.00 vs zdem_cpu 密集窗 11.41(50k 受控,遥测含在内)≈ **1.63×**;剔除 CPU 遥测负载后的纯物理对照会更低——本算例 64 粒子下并行的真实稳态收益有限,瓶颈段见"已知瓶颈"
- 物理验收(能量/静止判据)结果记录于 spec 验证表与任务报告:静止比例 60/64=93.8%,E 92.864→6.895 J 尾段单调缓降

## 与 zdem_cpu 对照的口径披露

1. **环路遥测**:zdem_cpu 主循环每步对每个包围球重叠对跑 tri-tri 相交→裁剪→环路遥测管线(仅计数不参与力;18k 步时 tri_checks≈2.1M/步,tri_ms≈11 ms/步);`zdem_mpi` 完全不含该管线。故"n=1 MPI 比 zdem_cpu 快 2.01×"主要反映遥测差+窗口差,**不是**通信层收益;跨 MPI 进程的并行收益应只看"vs n=1"列(2.71×)
2. 窗口差:11.41 为 50k 受控窗(含密集成堆段),本文 20k 窗以自由落体+首轮触底为主;GPU notes 已记录同窗 CPU 墙钟 7.398
3. CPU 参照为单线程 O(N²) broadphase + 环路遥测常开,非最优实现(GPU notes 同款声明)——引用 vs zdem_cpu 数字时需知悉

## 已知瓶颈(第一阶段记录,后续优化对象)

1. **每 rank O(n²) broadphase**:沿用 CPU 双循环(含 ghost 对枚举 (n_local+n_ghost)²/2),无空间哈希;GPU 版已有 CUB 排序 broadphase,反向移植属独立工作(spec 非目标)
2. **Newton-off 双算冗余**:跨域 pair 双方各算一次自己的半边,堆积场景 ~10-20% 计算冗余(spec 已知代价;大规模如成瓶颈切 Newton-on + reverse comm)
3. **每步全量 ghost 重建**:三轴链式 Sendrecv 每步整层重打包重交换,无增量更新(设计第一版;B 阶段接口已留)
4. **每步迁移重打包分配**:migration 每步构造发送缓冲(vector 分配),稳态下多数步为空迁移仍走全流程(review 记录在案)
5. **静态分解负载不均**:rank_n 6,26,25,7 → 最重 rank 41% 粒子;步时 = max(rank),理想均衡下 n=4 还有 ~(26/16) 的额外空间;动态重分区接口已预留(非目标)

## 单机共享内存上限判断

- 20k 窗 n=4 步时 2.09 ms 中约 0.67 ms(32%)为不可扩展开销;稳态接触段步时升至 ~7.0 ms(计算变重,固定开销占比相应下降),但加速比同时受负载不均压制;64 粒子可分性有限,**本算例单机有效上限就在 4 进程附近**
- 通信本身在共享内存通道上很便宜;第一阶段的价值是把通信路径(分解/迁移/ghost/gather)按真实网络语义打通并验证,集群/多 GPU 扩展的收益预期来自 10⁴–10⁶ 粒子量级(每 rank 工作量增长快于通信),不在本算例
- 输出路径(gather 到 rank0 写盘)在本算例不是瓶颈(125 帧 × ~0.12 s ≈ 15 s,占全程 ~1%);10⁶ 粒子时需改分布式 IO(记录为后续)
